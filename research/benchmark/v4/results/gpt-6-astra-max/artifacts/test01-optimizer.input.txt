# Semi-Formal Prompt Optimizer (v4.2.0)

## Overview

This skill rewrites vague, brittle, or goal-biased prompts into verifiable **reasoning certificates** grounded in eleven peer-reviewed research papers. It is completely tool-agnostic and model-agnostic: the optimized prompts work across Claude Code, Antigravity, Gemini CLI, OpenAI Codex CLI, Qwen Code, GitHub Copilot, Cursor, Windsurf, API pipelines, and chat interfaces.

## Research Foundation (11 Papers)

Each principle in this workflow traces to an empirical finding. For full summaries and citations, read `references/research-principles.md`.

1. **[META] Semi-Formal Reasoning** (Ugare & Chandra, 2026, arXiv:2603.01896): Requiring explicit Premises, Evidence Traces, and a Formal Conclusion improves analytical accuracy by 10 to 15 percentage points and cross-architecture quality by +25.9% at ~2.2x average token cost.
2. **[GOAL-BLIND] Purpose-Conditioned Cognition** (Cao, Jiang & Xu, 2026, arXiv:2602.09504): Disclosing downstream goals, business stakes, or evaluation metrics biases intermediate reasoning and degrades out-of-sample generalization. Prompts must specify what to analyze or build, never why or how it will be judged.
3. **[ACE] Agentic Context Engineering** (Zhang, Hu et al., 2026, arXiv:2510.04618): Itemized bullets with unique identifiers (`[P1]`, `[T1]`) prevent brevity bias and context collapse (+10.6% on agent benchmarks, 86.9% lower adaptation latency via incremental delta edits).
4. **[HIERARCHY] Instruction Hierarchy Failure** (Geng et al., 2025, arXiv:2502.15851): System/user message separation achieves only 9.6% to 45.8% compliance on conflicting constraints, whereas expertise and consensus framing ("The standard analytical protocol requires...") achieves 54% to 77.8% compliance.
5. **[CODE-SMELLS] LLM Integration Smells** (Mahmoudi et al., 2025, arXiv:2512.18020): 40.5% of LLM systems lack structured output schemas, causing silent downstream failures. Pair the reasoning certificate with an explicit JSON or typed schema whenever output is parsed programmatically.
6. **[PRISM] Persona Calibration** (Hu, Rostami & Thomason, 2026, arXiv:2603.18507): Expert personas improve alignment tasks (+0.4 to +0.65 MT-Bench) but damage accuracy tasks (-3.6 to -5.3 pp on MMLU). Omit personas on accuracy tasks, cap at 5 words on mixed tasks, and use full personas only on alignment tasks.
7. **[VS] Verbalized Sampling** (Zhang et al., 2025, arXiv:2510.01171): Post-training typicality bias causes mode collapse. Prompting the model to verbalize a candidate distribution with estimated typicality probabilities before committing increases creative and open-ended diversity by 1.6x to 2.1x.
8. **[SLOPSHAPE] Structural Signatures of AI Writing** (Madler, 2026, arXiv:2609.15369; Russell et al., 2026): Discourse-level structural features detect AI writing at 98.0 macro-F1 even after full rewording (10 core features reach 93.5 macro-F1). AI text clusters in a "tidy, self-announcing shape" (payoff in title, thesis before first section, formulaic legacy-vs-modern contrast, editorial-explainer voice, and restated-thesis summary endings). Creative and editorial prompts must enforce structural rarity rules.
9. **[CONTEXT-FILES] Repository Context File Evaluation** (Gloaguen et al., 2026, arXiv:2602.11988): LLM-generated `AGENTS.md` and `CLAUDE.md` files reduce coding agent task success by 3% while raising inference cost by over 20%, and directory overviews fail to speed up file localization. Persistent context files must contain only non-inferable tooling commands and hard boundary invariants.
10. **[HARNESS] Harness Routing, Context-as-a-File & Plan Verification** (Lee et al., 2026, arXiv:2603.28052; Zhang et al., 2026, arXiv:2606.09498; Shao et al., 2026, arXiv:2609.37725; Nam et al., 2025, arXiv:2509.21825): Model-specific harnesses (+14.2 to +21.4 pp on Terminal-Bench-2.0), file-backed context state (+11.4% accuracy with 21.5% fewer FLOPs), and plan-sufficiency gates outperform static bloated prompts. For Large Reasoning Models (LRMs), verification gates replace verbose step-by-step output narration to prevent overthinking loops.
11. **[SKILLS-SDO] Skill Residency & Positive Recipe Shaping** (Yin et al., 2026, arXiv:2608.12610): Under competing incentives, negative prohibitions ("Do not X") backfire and increase violations compared to positive structural recipes and conditionals keyed to observable predicates ("When condition X holds, output Y").

### The Prompt Structure Framework

| Component | Certificate Mapping & Research Rule |
|---|---|
| **IDENTITY** | Omit for accuracy tasks and LRMs; cap at 5 words for mixed tasks; use full persona only for alignment/style tasks (`[PRISM]`). |
| **TASK** | State what artifact or analysis to produce in goal-blind terms; strip downstream evaluation metrics, business stakes, and audience agendas (`[GOAL-BLIND]`). |
| **CONTEXT** | Declare as itemized `[P1]`, `[P2]` Premises (`[ACE]`). For repo `AGENTS.md`/`CLAUDE.md` files, prune directory trees and inferable rules (`[CONTEXT-FILES]`). |
| **CONSTRAINTS** | Enforce the selected Certificate Mode using expertise/consensus authority framing (`[HIERARCHY]`) and positive observable-predicate conditionals (`[SKILLS-SDO]`). |
| **OUTPUT FORMAT** | Require a Formal Conclusion citing `[T]` identifiers, a mandatory `REMEDIATION / NEXT ACTION` block, and a typed JSON schema if parsed downstream (`[CODE-SMELLS]`). |

## The Optimization Workflow

Follow these steps in order whenever a user asks to optimize, harden, or review a prompt or context file.

### Step 0: Check Skip Conditions (Anti-Overhead Guardrail) (`[META]`, `[HARNESS]`)

Before applying a certificate template, evaluate whether structured scaffolding should be skipped (Ugare & Chandra, 2026; Lee et al., 2026):
- **Trivial single-step requests** (single-line syntax fixes, simple factual lookups, pure formatting tweaks, or direct command translations): Skip full certificate compilation and apply only a 1-to-3 line goal-blind clarity cleanup.
- **Ultra-compact models (`<8B` parameters)**: Full multi-step pre-answer tables cause token starvation on sub-8B models; use a minimal 2-premise (`[P1]-[P2]`) prompt or direct code-first instruction.

### Step 1: Classify the Task Type & Target Model Tier (`[PRISM]`, `[HARNESS]`)

Determine the primary cognitive demand of the prompt and the capacity tier of the target model:
- **Accuracy-dependent** (code verification, bug hunting, math, fact extraction, legal/medical/financial analysis, compliance): **Omit persona**.
- **Mixed** (technical reports, architecture reviews, data analysis with executive presentation): **Minimal persona** (5 words or fewer, such as `"You are a systems analyst."`).
- **Alignment-dependent** (formatting, tone translation, style guides): **Full persona**.
- **Creative / Divergent** (copywriting, essays, storytelling, product messaging, ideation): **Minimal or Full persona**, routed to **Mode 4 (Creative & Divergent v2)**.
- **Persistent Context / Agent Harness** (`AGENTS.md`, `CLAUDE.md`, `.cursorrules`, system prompts, multi-turn agent loops): **Omit persona**, routed to **Mode 3 (LRM / Harness Mode)**.
- **Model-Aware Mode Routing**: Default to **Mode 2 (Lite Certificate)** for flash-tier or sub-30B parameter models to prevent token bloat and output starvation (Ugare & Chandra, 2026; Lee et al., 2026), reserving **Mode 1 (Max Certificate)** for frontier reasoning architectures or mission-critical human review.

### Step 1b: Select Certificate Mode (4 Modes)

Choose the certificate mode that matches the task stakes, model family, and execution environment:

| Mode | When to Use | Overhead | Structure Summary |
|---|---|---|---|
| **1. Max Certificate** | Frontier reasoning architectures or mission-critical human review (security, medical, legal, financial), low baseline competence, full auditability | ~2.2x | Exhaustive `[P]` Premises + multi-step `[T]` Evidence Traces + Formal Conclusion + Remediation + Self-Check |
| **2. Lite Certificate** | Default for flash-tier or sub-30B parameter models, and routine analytical tasks (standard code reviews, basic comparisons, everyday debugging) | ~1.5x | Max 3 `[P]` Premises + single-line causal arrows (`[T1] Input -> Step -> Finding`) + 1-2 sentence conclusion + Remediation |
| **3. LRM / Harness Mode** | Reasoning models (o3, DeepSeek-R1, Claude Extended Thinking, Gemini Thinking), algorithmic concurrency coding, OR `AGENTS.md` / `CLAUDE.md` / agent system prompts | ~1.1x to 1.3x | For LRMs & concurrency coding: Compact `[P]` Premises + Complete Executable Implementation First + Post-Hoc Verification Gate (`[V1] Concurrency & State Invariants -> [V2] Executable Self-Test Harness`, `<25%` verification overhead). For `AGENTS.md`: Minimal Viable Context pruning (`[CONTEXT-FILES]`, `[HARNESS]`) |
| **4. Creative & Divergent v2** | Copywriting, essays, blog posts, storytelling, brand messaging, open-ended ideation | ~1.6x | Backstage `[NT0]` Verbalized Sampling distribution + `[NT1]`-`[NT3]` Narrative Traces + `[SLOPSHAPE]` structural rarity contract + clean final prose |

### Step 2: Pre-Flight Anti-Dilution Sanitizer & Failure Diagnosis

Mechanically scan and repair the user's input against six empirical failure patterns before injecting any certificate structure:
1. **Conclusion-first reversal & instruction dilution (`[META]`, `[HIERARCHY]`)**: Strip or relocate directives like *"Lead with the final answer"*, *"State the verdict first"*, or competing style fluff so the model completes its `[P]` -> `[T]` verification trace before emitting its conclusion (Ugare & Chandra, 2026; Geng et al., 2025).
2. **Goal leakage (`[GOAL-BLIND]`)**: Strip references to why the user wants the output, business stakes, timelines, or how it will be graded so the model acts as a neutral analytical sensor (Cao, Jiang & Xu, 2026).
3. **Guesswork & persona traps (`[META]`, `[ACE]`, `[PRISM]`)**: Strip flowery expert roleplay (*"You are a 10x world-class..."*) on accuracy/coding tasks (-5.3pp MMLU penalty per Hu, Rostami & Thomason, 2026) and identify where the model might infer from symbol names instead of tracing concrete artifacts.
4. **Weak priority framing & mid-prompt burial (`[HIERARCHY]`)**: Replace polite requests (*"please make sure"*) with protocol authority framing (*"The standard analytical protocol requires..."*) and anchor inviolable verification rules at the very end of the prompt to leverage recency bias (Geng et al., 2025).
5. **Negative prohibition traps (`[SKILLS-SDO]`)**: Convert bare *"Do not X"* or *"Don't hallucinate"* lists into positive structural recipes and observable-predicate conditionals (Yin et al., 2026).
6. **Context bloat, LRM overthinking & SlopShape risk (`[CONTEXT-FILES]`, `[HARNESS]`, `[VS]`, `[SLOPSHAPE]`)**: Strip static `/init` directory trees from `AGENTS.md`/`CLAUDE.md` (Gloaguen et al., 2026), avoid forcing visible pre-code tables on reasoning/compact models (Lee et al., 2026), and enforce `[NT0]` + `[SC0]` on creative writing (Zhang et al., 2025; Madler, 2026).

### Step 3: Select and Adapt the Certificate Structure

#### Mode 1 & Mode 2 Pattern (Max and Lite Analytical Certificates)

```markdown
The standard analytical protocol for [DOMAIN] requires completing this reasoning certificate before issuing any verdict.

### PREMISES
Declare all observable inputs, constraints, and starting assumptions (cap at 3 items in Lite mode):
- [P1] Primary artifact(s) examined: [exact files, sections, or data]
- [P2] Applicable rules or invariants: [concrete specifications or constraints]
- [P3] Unverified inputs or environmental assumptions: [explicitly listed]

### EVIDENCE TRACES
Walk through the concrete path for each item (in Lite mode, use single-line arrows: `[T1] Input -> Operation -> Observable Result`):
- [T1] Trace [item 1]: [step-by-step verification with exact citations to P1-P3]
- [T2] Trace [item 2]: [step-by-step verification with exact citations to P1-P3]

### FORMAL CONCLUSION
Derive your verdict solely from the premises and traces above:
- Verdict: [objective disposition]
- Supporting traces: [cite T1, T2, etc. for every claim]
- Verification gaps: [list any path marked UNABLE TO TRACE and the missing input required]

### REMEDIATION / NEXT ACTION
The task is incomplete until this section contains one of the following:
- A complete, copy-pasteable fix (patch, revised text, corrected query, or executable command)
- A concrete sequence of verification commands to resolve any Verification Gaps
- The explicit statement: "No remediation required: [reason grounded in T-identifiers]"
```

#### Mode 3 Pattern A: Large Reasoning Model (LRM) & Algorithmic Verification Certificate (Template 12)

```markdown
### 1. COMPLETE EXECUTABLE IMPLEMENTATION (Generated First)
Provide the complete, copy-pasteable implementation satisfying [P1] and [P2] before emitting any verification tables or test prose.

### 2. POST-HOC VERIFICATION GATE ([V1] Concurrency & State Invariants -> [V2] Executable Self-Test Harness)
- [V1] Concurrency & State Invariants: Check each invariant in [P2] (`[SATISFIED / VIOLATED] -> [exact line/mechanism in implementation]`).

```

```markdown

- [P1] Reader & context: [who is reading, what concrete problem or situation they are in]
- [P2] Target shift: [what specific realization or emotional shift the piece must produce]
- [P3] Voice & constraints: [perspective, length, format, and domain boundaries]

### BACKSTAGE SCAFFOLD (complete first, or enclose in <backstage> tags)
- [NT0] Verbalized Distribution Sampling: Enumerate 4 structurally distinct angles for this piece, assigning each an estimated typicality probability (p) reflecting how often a default AI would pick it:
  1. [Angle 1: prototypical/safe] (p = ...)
  2. [Angle 2: moderate variation] (p = ...)
  3. [Angle 3: low-typicality, concrete angle] (p = ...)
  4. [Angle 4: contrarian or unexpected structural entry] (p = ...)
  Selection: Commit to the strongest angle with p <= 0.20 that fulfills [P1]-[P3].
- [NT1] Audience Friction: [what specific skepticism or lived detail opens the piece?]
- [NT2] Structural Trajectory: [map the progression so the thesis emerges from evidence rather than being pre-announced]
- [NT3] Register & Cadence: [concrete nouns, varied paragraph lengths, and practitioner voice choices]

### STRUCTURAL RARITY CONTRACT (anti-SlopShape rules for the final draft)
Construct the final piece to satisfy these four discourse rules:
1. Title & Opening: Open inside a specific moment, artifact, or tension; reserve the core thesis until after the first concrete evidence unit.
2. Argument Flow: Build the argument through direct evidence and causal progression rather than a formulaic "Old Way vs. New Way" contrast.
3. Voice: Write from a grounded practitioner perspective with specific domain texture rather than an institutional "editorial explainer" voice.
4. Ending: Close on a concrete implication, sharp edge case, or external action pathway rather than a summary synthesis paragraph that restates the thesis.

### FINAL OUTPUT
Present the finished piece cleanly, embodying the selected [NT0] angle and the Structural Rarity Contract.
```

### Step 4: Apply Positive Recipe Guards, Data Binding & Self-Check (`[SKILLS-SDO]`, `[META]`, `[ACE]`)

Enforce **Self-Contained Data Binding**: The rewritten prompt must embed all input code, tables, numbers, and case facts directly inside the prompt premises; never leave empty placeholders like `[insert code here]` or refer to external context (Ugare & Chandra, 2026; Zhang, Hu et al., 2026).

Replace negative "Do NOT" lists with **observable-predicate conditionals** and append the mandatory **Traceability Self-Check** to every analytical prompt:

```markdown
VERIFICATION & TRACEABILITY CONTRACT:
- Data-binding predicate: Embed all input code, tables, numbers, and case facts verbatim inside [P1]-[Pn] so the prompt is 100% self-contained without placeholders.
- Grounding rule: Base every step in [T] traces on explicit implementation details, data points, or text in [P1]-[Pn] rather than symbol names or titles.
- Missing-evidence predicate: When a path cannot be verified from [P1]-[Pn], record `UNABLE TO TRACE: [exact missing input]` in the trace and list it under Verification Gaps.
- Counterexample predicate: When disconfirming evidence or edge-case failures appear in [P1]-[Pn], record them as a dedicated `[T]` trace even if the overall verdict is positive.
- Neutrality predicate: Derive the Verdict strictly from `[T]` traces without referencing downstream business goals, timelines, or evaluation rubrics.

TRACEABILITY SELF-CHECK (mandatory before finalizing):
Verify that every claim in your Formal Conclusion cites at least one `[T]` or `[V]` identifier from above. If any claim lacks a supporting identifier, either add the missing trace from [P1]-[Pn] or remove the claim so zero orphaned conclusions remain.
```

SOURCE FILE: make-prompt-better/references/research-principles.md
# Research Principles Index

Quick reference for explaining why specific optimization decisions were made. Each entry maps a research paper to its actionable constraint on prompt, context, and harness design.

---

## [META] Semi-Formal Reasoning (Ugare & Chandra, 2026)
arXiv: 2603.01896

**Finding:** Structured reasoning templates (premises, traces, conclusion) improved accuracy 10 to 15 percentage points across code analysis tasks (78% to 88% on curated patch equivalence, 93% on real-world patches, 78% to 87% on code QA, +5 to 12 pp on Top-5 fault localization) by preventing the model from skipping cases or making unsupported claims. Cross-architecture benchmarking shows an average token overhead of ~2.2x for a +25.9% relative improvement.

**Constraint:** Every optimized analytical prompt must include the certificate structure. The model states premises before tracing, and traces before concluding. Conclusions must reference traces by identifier.

**When to cite:** Explaining why the prompt has a structured certificate scaffold.

---

## [GOAL-BLIND] Purpose-Conditioned Cognition (Cao, Jiang & Xu, 2026)
arXiv: 2602.09504

**Finding:** Telling an LLM how its output will be used (for example, "this will predict stock returns" or "we need to pass tomorrow's client demo") causes the model to reshape intermediate outputs toward the disclosed goal. In-sample performance improved, but out-of-sample generalization degraded. The effect disappeared after the model's knowledge cutoff, confirming exploitation of training correlations rather than genuine signal improvement.

**Constraint:** Omit evaluation criteria, downstream use cases, business stakes, and success metrics from the prompt. Specify what to measure, trace, or build, never why or how the result will be judged downstream.

**When to cite:** Explaining why language like "this will be used to...", "the goal is to predict...", or "we are a small startup negotiating with..." was removed from the prompt.

---

## [ACE] Agentic Context Engineering (Zhang, Hu et al., 2026)
arXiv: 2510.04618 (ICLR 2026)

**Finding:** Contexts perform best as structured, itemized playbooks with unique identifiers per entry. Two failure modes degrade prompts: brevity bias (optimization collapses to short generic instructions that omit domain specifics) and context collapse (iterative full rewrites erode accumulated detail). Incremental delta updates outperform full rewrites (+10.6% on agent tasks, +8.6% on finance benchmarks, 86.9% lower adaptation latency).

**Constraint:** Use numbered identifiers (`[P1]`, `[T1]`) for every premise and trace so conclusions can cross-reference them. Prefer explicit domain detail over generic brevity in task certificates. When iterating across sessions, make targeted delta edits rather than rewriting the whole prompt.

**When to cite:** Explaining why premises and traces have `[P1]` and `[T1]` identifiers, or why iterative updates use delta edits.

---

## [HIERARCHY] Instruction Hierarchy Failure (Geng et al., 2025)
arXiv: 2502.15851 (AAAI 2026)

**Finding:** System/user prompt separation achieves only 9.6% to 45.8% compliance on conflicting constraints. Societal hierarchy framings achieve 54% to 77.8% compliance: consensus ("90% of experts recommend...") is strongest, expertise ("peer-reviewed methodology requires...") is second, and authority ("leadership requires...") is third. Models also exhibit strong inherent biases toward lowercase text, longer outputs, and keyword avoidance.

**Constraint:** Frame the certificate structure using expertise or consensus language ("The standard analytical protocol requires...") rather than relying on system message placement alone. Reinforce constraints that fight model defaults, especially length caps and brevity constraints.

**When to cite:** Explaining why the preamble uses phrases like "established methodology requires" instead of "please fill out this template."

---

## [CODE-SMELLS] LLM Code Smells (Mahmoudi et al., 2025)
arXiv: 2512.18020

**Finding:** 60.5% of 200 audited open-source LLM systems have integration code smells. Most relevant is "No Structured Output" (40.5% prevalence): when LLM outputs are parsed downstream without enforced schemas, silent failures occur from schema drift, missing fields, and type mismatches. Other common smells include unbounded max tokens (38%), no model version pinning (36%), no system message (34.5%), and unset temperature (36.5%).

**Constraint:** When the optimized prompt's output will be parsed programmatically or piped into another tool, add an explicit JSON schema or typed output specification alongside the certificate. The certificate is the reasoning scaffold; the output format is the delivery contract.

**When to cite:** Explaining why a JSON schema wrapper was added for pipeline or API prompts.

---

## [PRISM] Persona Effects (Hu, Rostami & Thomason, 2026)
arXiv: 2603.18507

**Finding:** Expert persona prompts help alignment-dependent tasks (format following, safety, style: +0.4 to +0.65 on MT-Bench categories) but damage accuracy-dependent tasks (MMLU drops from 71.6% to 66.3% to 68.0%). Longer personas damage accuracy more. Minimal personas ("You are a data analyst." at 5 words or fewer) limit accuracy damage on mixed tasks. Reasoning-distilled models (such as DeepSeek-R1 or o-series variants) benefit from context detail rather than persona identity.

**Constraint:** Classify each task before adding persona:
- Accuracy task (fact retrieval, classification, math, code verification): omit persona
- Alignment task (format, style, safety, tone): include full persona
- Mixed task: use minimal persona (5 words or fewer)
- Reasoning-distilled model: omit persona

**When to cite:** Explaining why an identity or persona line was omitted, capped at 5 words, or expanded.

---

## [VS] Verbalized Sampling for Diversity (Zhang, Yu, Chong, Sicilia, Tomz, Manning & Shi, 2025)
arXiv: 2510.01171

**Finding:** Post-training alignment (RLHF, DPO) induces mode collapse driven by typicality bias in human preference data, where annotators systematically favor familiar, prototypical responses. Prompting the model to verbalize a probability or typicality distribution over a set of candidate responses (for example, generating 3 to 5 distinct candidates with estimated typicality probabilities and sampling from the lower-typicality tail) circumvents mode collapse without sacrificing accuracy or safety. In creative writing, dialogue simulation, and open-ended synthesis, Verbalized Sampling increases output diversity by 1.6x to 2.1x, with larger gains on more capable models.

**Constraint:** For creative, editorial, brainstorming, and multi-hypothesis prompts, include a backstage `[NT0] Verbalized Distribution Sampling` trace that enumerates 3 to 5 structurally distinct candidate angles with estimated typicality probabilities (`p`), then selects the strongest low-typicality angle (`p < 0.25`) that satisfies all premises.

**When to cite:** Explaining why creative or divergent prompts generate multiple probability-weighted candidate angles before drafting the final piece.

---

## [SLOPSHAPE] Structural Signatures of AI Writing (Madler, 2026; Russell et al., 2026)
arXiv: 2609.15369

**Finding:** Word-level AI detectors collapse under paraphrasing (DetectGPT drops from 70.3% to 4.6%), but discourse-level structural features detect AI commercial writing at 98.0 macro-F1 (and 98.1 after full self-rewording; StoryScope found 93.2 macro-F1 on fiction). Just 10 core structural features achieve 93.5 macro-F1. AI writing crowds into a "tidy, self-announcing shape" (mean structural rarity percentile 0.435 vs. human 0.838, Cohen's `d = 1.83`): promising the payoff in the title (`PUR_OUT_003`), stating the thesis before the first section (`STR_FLW_006`), setting up a formulaic legacy-versus-modern contrast (`STR_FLW_005`), artificial stakes escalation (`AUD_STK_005`), an editorial-explainer voice (`VOC_VOX_001`), and ending with a restated-thesis or summary synthesis stage (`STR_STG_008`, `STR_STG_001`) while omitting external participation pathways (`VOC_PRT_005`).

**Constraint:** When optimizing creative, editorial, or commercial writing prompts, enforce structural rarity rules in the output contract: (1) open with a concrete observation, friction point, or specific artifact rather than a thesis pre-announcement; (2) develop the thesis inductively rather than front-loading a legacy-versus-modern contrast; (3) adopt a specific practitioner or first-person perspective rather than an institutional explainer voice; and (4) end on a concrete implication or external participation pathway rather than a summary synthesis paragraph.

**When to cite:** Explaining why creative and writing prompts constrain discourse structure and conclusion behavior rather than just banning cliched words.

---

## [CONTEXT-FILES] Repository Context File Evaluation (Gloaguen, Mundler, Muller, Raychev & Vechev, 2026)
arXiv: 2602.11988

**Finding:** Across coding agents (Claude Code, Codex, Qwen Code, Sonnet 4.5, GPT-5.2) on SWE-bench and AGENTBENCH, LLM-generated repository context files (`AGENTS.md`, `CLAUDE.md`) reduced task resolution success by 3% on average while increasing inference costs by over 20% and increasing steps before first file interaction. Developer-written context files improved success by +4% on average (at up to 19% higher cost), but codebase directory overviews (included in 8 of 12 files) failed to speed up file localization. Because agents strictly obey context files, unnecessary instructions trigger redundant file traversal, grep calls, and test runs.

**Constraint:** When optimizing persistent system prompts, `AGENTS.md`, `CLAUDE.md`, or cursor/windsurf rule files, apply the Minimal Viable Context rule: omit auto-generated directory trees, codebase overviews, and generic coding platitudes. Include only (1) exact, non-inferable environment, build, lint, and test commands (such as `uv`, custom scripts, or specific flags), and (2) hard architectural boundary invariants that cannot be discovered by reading the code.

**When to cite:** Explaining why directory trees, file inventories, and generic style guidelines were stripped when optimizing an `AGENTS.md`, `CLAUDE.md`, or system prompt.

## [HARNESS] Harness Optimization, Context-as-a-File & Plan Verification (Lee et al., 2026; Zhang et al., 2026; Shao et al., 2026; Nam et al., 2025)
arXiv: 2603.28052 (Meta-Harness), arXiv: 2606.09498 (Self-Harness), arXiv: 2609.37725 (CLM), arXiv: 2509.21825 (DS-STAR)

**Finding:** Agent performance is jointly determined by the model and its operating harness. Meta-Harness shows that optimizing how context is retrieved and presented outperforms static context playbooks by +7.7 points while using 4x fewer context tokens. Self-Harness shows that harness design is model-specific (+14.2 to +21.4 pp pass rate on Terminal-Bench-2.0 across MiniMax, Qwen3.5, and GLM-5). Context Language Models (CLMs) show that treating context as an editable file improves accuracy by +11.4% with 21.5% fewer FLOPs on BrowseComp-Plus. DS-STAR demonstrates that inserting an explicit plan-sufficiency verification gate before execution achieves state-of-the-art accuracy on multi-source data science tasks. Meanwhile, for Large Reasoning Models (LRMs with native extended thinking), forcing verbose step-by-step CoT narration in the visible output triggers overthinking loops and inflates token costs.

**Constraint:** Route prompts by model and execution environment:
- For **Large Reasoning Models (LRMs)** (such as o3, DeepSeek-R1, Claude Extended Thinking, Gemini Thinking), use **LRM / Harness Mode**: keep Premises `[P1]` and Formal Conclusion with `[T]` evidence citations, but replace verbose step-by-step output narration with **Verification Gates** (pre-conditions and post-conditions the internal reasoning must satisfy before emitting the final artifact).
- For **Multi-Turn Agentic Workflows**, instruct the agent to externalize intermediate state to a scratchpad or state file (`Context-as-a-File`) and verify plan sufficiency before mutating target files.

**When to cite:** Explaining why an optimized prompt for a reasoning model or coding agent uses verification gates and file-backed state instead of verbose visible chain-of-thought narration.

## [SKILLS-SDO] Skill Residency & Positive Recipe Shaping (Yin, Li, Shi, Zhang, Seong & Wang, 2026)
arXiv: 2608.12610

**Finding:** Across 56,804 published `SKILL.md` files, installed skill descriptions sit permanently in the system prompt (50 to 280 tokens per skill every message), competing for an attention budget of fewer than 100 reliable slots. Furthermore, empirical wording evaluations show that negative prohibitions ("Do not X", "Never narrate") backfire under competing incentives, producing higher variance and more violations than positive structural recipes (stating the exact output parts in order) and conditionals keyed to observable predicates ("When condition X holds, output Y").

**Constraint:** Keep skill frontmatter descriptions compact, universal, and strictly focused on triggering conditions ("Use when..."). Within optimized prompts, express anti-hallucination and formatting rules as positive structural recipes and observable-predicate conditionals (for example, "When a trace lacks direct source evidence in [P1]-[Pn], record `UNABLE TO TRACE: [missing artifact]` and exclude the claim from the Verdict") rather than bare prohibition lists.

**When to cite:** Explaining why negative "Do NOT" rules were rewritten into positive conditional recipes, or why skill metadata uses trigger-only descriptions.
