# Support

For installation, start with the [quickstart](docs/quickstart.md). Preview local changes with `./install.sh --dry-run`; inspect selected installations with `./install.sh --check`. For duplicates or recovery, use [troubleshooting](docs/installation.md#troubleshooting). For mode selection and limitations, read [when to use](docs/when-to-use.md).

Search [existing issues](https://github.com/poferraz/make-prompt-better/issues) before opening a bug report or question. Include the version or commit, operating system, agent runtime, command, expected behavior, and sanitized output. A small reproducible example helps more than a screenshot of a long conversation.

For npm setup, use the [publishing runbook](docs/npm-publishing.md). A public npm 404 is not fixed by asking customers for a token. A maintainer environment public-key 404 means the environment/access needs checking. Include an Actions run URL and sanitized error code for publishing issues; never include a token, `.npmrc` contents, or private credentials.

For research corrections, include the original source and relevant page or section. For security vulnerabilities, use the private contact in [SECURITY.md](SECURITY.md).

Support is provided by a volunteer maintainer with no guaranteed response time. GitHub Issues is the public support route; a separate discussion forum is unnecessary at the current activity level.
