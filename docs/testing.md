# Testing and recurring runs

See [continuous quality and scoped review](continuous-quality.md) for repeatable outcome campaigns, the routing experiment, bounded optional model review, and activation/retention rules.

From a full source checkout, run `npm run verify`. It runs structural validation, release metadata, both linters, Bash syntax, benchmark tests, and CLI, installer and actual npm archive integration tests. `npm run verify:fast` runs only structure, release metadata, lint and Bash syntax; it is not a substitute for the full release bar. Tests use temporary directories and a temporary npm cache; no model credentials are needed. These source verification tools are not included in the npm consumer package. The additional validation and synchronization requirements in [AGENTS.md](../AGENTS.md) still apply; for testing-only work, run the installer with an isolated temporary home.

The required check remains named `validate`. On every push and pull request to main, including documentation-only changes, it waits for three jobs: `source` runs `npm run verify`, `regression` calls the complete Linux/macOS matrix in `recurring-tests.yml`, and `package` calls `npm-preflight.yml`. The final job runs even when a dependency fails or is skipped, and accepts only success from all three. Package preflight packs once, audits and hashes the tarball, tests its installation lifecycle, and retains the checked artifact. None of these jobs receives npm credentials or publishes.

Keep the main branch rule requiring `validate` with the branch up to date. Preserve that name when editing workflows, and verify the rule in repository settings when applying these changes. A local edit does not change GitHub protection or prove that the hosted matrix ran. Administrators with a configured bypass can still bypass branch protection. Release preparation separately requires a successful main push run on the exact tagged commit; a PR run, stale commit, incomplete run listing, or older successful attempt cannot substitute for its latest result.

The recurring matrix is also configured for daily runs at 04:23 UTC and a deeper seeded property run on Sundays at 05:43 UTC. The matrix specifies Python 3.10 and 3.12 on Ubuntu, Python 3.12 on macOS, and Node.js 22. Package preflight additionally uses Node.js 24. The v4.4.0 release passed the earlier matrix; later changes must pass on their own commit. Manual dispatch accepts a numeric seed. Required CI uses seed 42; scheduled runs use the UTC date, each plus the next two integers. Reproduction commands and coverage reports are retained for 14 days. Each matrix job has a 20 minute timeout. The mutation probe runs on PRs, main pushes, manual dispatch and the weekly schedule. GitHub may delay or drop scheduled runs and disables schedules in inactive public repositories after 60 days.

Reproduce locally with `TEST_SEED=42 TEST_CASES=200 python3 -m unittest discover -s research/benchmark/v4 -p 'test_*.py' -v` and `python3 -m unittest discover -s tests -v`. For the weekly budget use `TEST_CASES=2000`. Failure output identifies the seed and property case; use the run artifact's reproduction command to repeat it. Inspect job logs for failures before retrying and fix flaky tests rather than suppressing them.

Python coverage uses coverage.py 7.6.12 with branches enabled and includes the benchmark summary module as well as the existing production modules. CI uses an 81% combined floor and per-module floors in `tests/check_python_coverage.py`. JavaScript coverage uses c8 10.1.3 across the two production modules, with overall floors of 85% lines and 78% branches, and per-module floors of 83% and 78%. Floors do not establish safety or prevent every regression. Shell has no numeric coverage; unlisted scenarios remain gaps.

The mutation probe tests four targeted mutations. A loopback HTTP fixture tests a streamed response and retry without a model service. Live model behavior, interruptions at every possible instruction, all host discovery paths, and exhaustive mutations are not verified. No live paid inference is performed in CI.

## npm workflow and package checks

`tests/test_guided_install.py` drives the bare CLI through real pseudo-terminals and isolated homes/projects. It covers names and numeric choices, invalid input, both scopes, cancellation/EOF/interruption, repeated installation with recovery, redirected streams, explicit help/dry-run compatibility, installer failure, and a real mismatch introduced between installation and verification. `tests/test_integration.py` repeats the guided path from the actual npm archive. These are local filesystem tests and do not establish public availability of v4.5.1 or host discovery.

`tests/test_npm_release.py` checks stable release labels, published-release metadata, exact-commit main CI, archive identity, execute permissions, file boundaries, lifecycle hooks, credential patterns, size limits, registry error handling, and integrity mismatches. An actual tarball is installed into an isolated home and project to test explicit Codex initialization, repeats, six-copy migration, edited-copy rejection, recovery payload preservation, uninstall, and independence from the npm cache. Filesystem smoke tests do not simulate Codex discovery or model execution. The module has an 80% branch-aware coverage floor.

`.github/workflows/npm-preflight.yml` is shared by required validation and the manual `publish-npm.yml` workflow. Its checks have no npm credentials. The manual `check-token` operation uses the protected environment solely to call npm's identity endpoint; it logs no token or raw response. `publish` requires a stable tag on validated main and a published GitHub release before the environment reviewer can approve publication. It publishes the same run's checked artifact, then requires the separate credential-free public installation smoke. That public check runs after publication and cannot be required before the package exists. The implementation and fixture tests do not establish public npm installation or OIDC success. See [npm setup and verification](npm-publishing.md).

The `verify-public` operation checks an already published version without a publish job, npm credentials, or an environment approval. It retains the same stable-tag, source ancestry, exact-source CI, package audit, and trusted-integrity checks. Both operations retry public HTTP 404 responses at most 20 times with 15-second pauses, allowing npm processing to finish. Other HTTP failures and identity or integrity mismatches fail immediately. Verification never retries a publication. Workflow regression tests execute the real read-back code with simulated responses and exercise the job conditions for failed or skipped dependencies.

The actual public npm 4.5.0 smoke passed on macOS on 2026-11-06 using empty npm configurations, an isolated home, and fresh caches. [Dated public evidence](evidence/2026-11-06/v4.5.0-npm-verification.json) is separate from local registry fixtures and host discovery evidence.
